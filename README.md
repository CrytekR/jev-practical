# jev-practical

这个仓库研究 **Jev 类决策模型**怎么用、判断是怎么做出来的，以及上线前可以单独验证的优化。

Jev 是 TypeSafe 的 System One 模型。同一类接口还有开源读出实现：输入一份状态和若干预先写好的问题，返回封闭集合上的概率，不生成自由文本。一次请求里的问题共享状态、彼此看不到对方的答案。

| 原语 | 问法 | 程序拿到的结果 |
| --- | --- | --- |
| `choice` | 无序候选里选一个，2–255 项 | 选项、全体概率、由分布形状得到的集中度 |
| `score` | 2–10 个从低到高的等级 | 等级下标的期望、全体概率、集中度 |
| `noul` | 一条有真假标准的命题 | 命题为真的概率。接口不另给置信度 |

集中度用的是公开文档演示里的近似 `(n × 峰值 − 1) / (n − 1)`。它描述分布有多尖，不是「这次判断正确」的概率。厂商内部的统计和名为 RLCD 的训练配方没有公开；本仓库不复现这些权重。

## 研究怎么拆

| 问题 | 代码 |
| --- | --- |
| 哪些流程适合这种接口 | `scenarios.py`：分流、注入闸门、检索筛选、生成质检、文本状态上的动作选择、评审循环 |
| 判断怎么从候选分数变成答案 | `scoring.py`、`answers.py`、`readout.py` |
| 概率能不能当动作来用 | `metrics.py`、`calibrate.py`、`selective.py`、`score_shape.py` |
| 调用方式和问题契约怎么省、怎么少错 | `batching.py`、`design.py` |

`readout.py` 的词重叠模型只是可替换后端，用来观察选项描述怎样推动选择。清晰工单上它跟得住关键词；「请不要退款」会被「退款」吸进账单类。换上真实对数概率时，后面的校准、阈值和契约检查不用改。

## 针对性优化

这些手段分别动准确率、概率形状、覆盖率或成本，一次只改一层，并用自己的标注衡量。

1. **契约。** 候选要覆盖会真正出现的情况，并带上界定范围的描述；每题只判断一件事。缺兜底项时，模型仍会从剩下的选项里挑一个，集中度可以很高。依赖上一题答案的问题要拆成两轮，或由程序组合边缘概率。边缘概率相乘不是模型给出的联合分布。
2. **归约。** 多 token 候选可以用对数概率的和或平均收成一个分数。两种归约会让长短文本的名次对调，校准必须绑定其中一种。
3. **读出成本。** 选项很多时，每个选项用一个代号 token，状态只读一次。全文本读出的成本随选项 token 数增长。`batching.py` 里的可见位置对是方案比较，不是延迟预测。
4. **集中度之外看分差。** 峰值公式忽略亚军。第一名相同、第二名一远一近时，集中度一样，分差不一样。路由要抄送第二名时，用分差。
5. **在本任务标注上校准。** 温度缩放压平或变尖分布，正温度不改变 `choice` / `score` 的 argmax。是非题可以用 Platt。温度和斜率只属于这一次的任务、题型和读出归约。
6. **按成本接受。** 二元动作里，执行的阈值是误报成本 / (误报成本 + 漏报成本)，两类错误成本同为 2 和 8 时阈值是 0.2。报告接受集的覆盖率和错误率；没有样本被接受时，错误率无定义。
7. **分数不要只留一个期望。** `(0, 0.5, 0.5, 0)` 和 `(0.5, 0, 0, 0.5)` 的期望等级都是 1.5。损失随等级非线性增长时，按每级损失求期望，并看两个峰相距几级。
8. **级联。** 期望成本 = 额外处理 + 决策调用 + 回退率 × 回退成本。回退率高于盈亏平衡点时，全程走后备更便宜。
9. **代号偏置。** 固定字母会把 token 先验算进选择。评估时打乱代号与选项的对应，再看选择率是不是还粘着同一个字母。

权限、时序、鉴权和最终验收留在普通代码里。决策返回时核对状态版本，过期结果丢弃。

## 运行

```bash
python3 -m pip install -e .
python3 -m jev_practical
python3 -m pytest
```

`python3 -m jev_practical` 会跑一轮本地实验：过置信样本上的温度缩放、选择性接受、词重叠分流、期望损失、共享前缀、契约检查和级联成本。数字来自 `study.py`，不访问外部模型接口。未安装时可以用 `PYTHONPATH=src python3 -m jev_practical`；`pytest` 会通过 `pyproject.toml` 把 `src` 放进路径。
